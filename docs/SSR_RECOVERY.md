# Восстановление SSR гостевой главной

Краткая техническая инструкция. Восстанавливаются только сборки и процесс
SSR; полный откат приложения или БД этими шагами не выполняется и не
обещается.

## Что сохранить до выкладки

- Текущий коммит (`git rev-parse HEAD`, он же `APP_BUILD_SHA` в `.env`).
- Согласованную пару артефактов одной версии: каталоги `public/build/`
  (клиентский manifest и assets) и `bootstrap/ssr/` (SSR-бандл).
- Состояние процесса Supervisor `irsi-ssr` (`supervisorctl status irsi-ssr`).

`.env`, содержимое БД и логи в пару артефактов не входят и из этой
инструкции не восстанавливаются.

## Восстановление согласованных сборок

1. Привести рабочий каталог к нужному коммиту (например,
   `git pull --ff-only origin main` или откат к сохранённому SHA).
2. Собрать обе сборки из одного и того же коммита:

   ```bash
   npm ci
   npm run build:ssr   # vite build && vite build --ssr
   ```

3. Проверить, что артефакты существуют и непусты:
   - `bootstrap/ssr/ssr.js` (или путь из `inertia.ssr.bundle`, если задан);
   - `public/build/manifest.json` (каталог `build` — из конфигурации
     laravel-vite-plugin в `vite.config.ts`).

   Клиентская и SSR-сборки обязаны быть из одного коммита: смешение
   артефактов разных версий даёт несогласованный рендер.

## Адресный перезапуск и проверка

1. Перезапустить только процесс SSR, не глобальный restart:

   ```bash
   sudo supervisorctl restart irsi-ssr
   ```

2. Проверить здоровье процесса:

   ```bash
   php artisan inertia:check-ssr
   ```

3. Проверить настоящий SSR гостевой главной (не только HTTP 200):

   ```bash
   curl -sS -o /tmp/home.html -w '%{http_code}\n' https://irsi-app.ru/
   ```

   Успешной считается только страница, где:
   - HTTP 200;
   - в корне приложения есть серверный контент
     (`data-server-rendered="true" id="app"`), а не пустой `#app`;
   - внутри корня присутствует H1 «Онлайн-запись»;
   - в head есть `<link rel="canonical" href="https://irsi-app.ru/">`.

   Ответ 200 с CSR-fallback (пустой `#app`, содержимое только в
   Inertia JSON) проверкой не проходит. Поиск текста внутри
   Inertia JSON проверкой SSR не считается.

Если публичная проверка не прошла — вернуть режим обслуживания
(`php artisan down`) и повторить восстановление сборок и перезапуск;
SSR не отключать ради «зелёной» проверки.
