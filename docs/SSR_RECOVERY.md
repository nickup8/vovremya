# Восстановление SSR гостевой главной

Краткая техническая инструкция. Восстанавливаются только пара сборок и
процесс SSR; полный откат приложения или БД этими шагами не выполняется и
не обещается.

## Что сохранить до выкладки

- Текущий коммит (`git rev-parse HEAD`, он же `APP_BUILD_SHA` в `.env`).
- Проверенную пару артефактов одной версии: каталоги `public/build/`
  (клиентский manifest и assets) и `bootstrap/ssr/` (SSR-бандл) — вместе,
  одним архивом, с указанием коммита, из которого они собраны.
- Состояние процесса Supervisor `irsi-ssr` (`supervisorctl status irsi-ssr`).

`.env`, содержимое БД и логи в пару артефактов не входят и из этой
инструкции не восстанавливаются.

## Восстановление сохранённой пары из бэкапа (основной способ)

Пара артефактов совместима с кодом только того коммита, из которого она
собрана. Перед восстановлением убедитесь, что рабочий каталог находится
на этом коммите (`git rev-parse HEAD` сверяется с SHA, записанным при
сохранении бэкапа). `git pull` способом возврата к сохранённому SHA не
является: он приводит каталог к вершине `origin/main`, а не к сохранённой
версии. Если каталог не на нужном коммите — сначала приведите код к нему
по вашей процедуре отката кода, затем восстанавливайте пару.

Порядок восстановления обеих каталогов из проверенного бэкапа:

1. Остановить вывод приложения в обслуживание, если он ещё не включён:
   `php artisan down --render="errors::503" --retry=60`.
2. Распаковать бэкап-архив в рабочий каталог так, чтобы восстановились
   оба каталога одной версии (пример):

   ```bash
   tar -xzf /путь/к/бэкапу/ssr-pair-<SHA>.tar.gz -C /var/www/irsi-app
   ```

3. Проверить, что восстановлены именно эти каталоги и они непусты:
   - `bootstrap/ssr/ssr.js` (или путь из `inertia.ssr.bundle`, если задан);
   - `public/build/manifest.json` (каталог `build` — из конфигурации
     laravel-vite-plugin в `vite.config.ts`);
   - по возможности сверить SHA из имени архива с `git rev-parse HEAD`.

   Клиентская и SSR-сборки обязаны быть из одного коммита: восстанавливать
   каталоги по одному или из разных бэкапов нельзя — смешение версий даёт
   несогласованный рендер.

## Альтернатива: пересборка

Если бэкапа пары нет, а доступна только пересборка — соберите обе сборки
из одного и того же коммита (только после того, как код приведён к нему):

```bash
npm ci
npm run build:ssr   # vite build && vite build --ssr
```

Проверка непустоты артефактов — та же, что выше. Пересборка не заменяет
бэкап: она требует рабочего окружения и того же SHA кода.

## Порядок восстановления из режима обслуживания

Выполнять строго по шагам; публичная HTML-проверка идёт после `artisan up`,
иначе она получит 503 и результат будет недостоверен:

1. Восстановить пару каталогов из бэкапа (или пересобрать — см. выше).
2. Адресный перезапуск только процесса SSR, не глобальный restart:

   ```bash
   sudo supervisorctl restart irsi-ssr
   ```

3. Проверить здоровье процесса:

   ```bash
   php artisan inertia:check-ssr
   ```

4. Снять режим обслуживания:

   ```bash
   php artisan up
   ```

5. Проверить настоящий SSR гостевой главной (не только HTTP 200):

   ```bash
   curl -sS -o /tmp/home.html -w '%{http_code}\n' https://irsi-app.ru/
   ```

   Успешной считается только страница, где:
   - HTTP 200;
   - в корне приложения ровно один `#app` с непустым серверным контентом
     (`data-server-rendered="true"`), а не пустой корень;
   - ожидаемый текст «Онлайн-запись» присутствует в H1 внутри этого корня
     (текст вне H1 и внутри script/JSON не считается);
   - в `head` ровно один `<link rel="canonical">`, его `href` строго равен
     `https://irsi-app.ru/` (подстрока не принимается).

   Ответ 200 с CSR-fallback (пустой `#app`, содержимое только в Inertia
   JSON) проверкой не проходит. Поиск текста внутри Inertia JSON проверкой
   SSR не считается. Проверку выполнять с таймаутом (например,
   `curl --max-time 20`).

6. Если публичная проверка не прошла — снова включить режим
   обслуживания:

   ```bash
   php artisan down --render="errors::503" --retry=60
   ```

   и вернуться к шагу 1 (восстановление пары). SSR не отключать ради
   «зелёной» проверки.
